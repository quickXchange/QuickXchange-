---
name: Website Telegram support scope
description: Purpose and publication boundaries for the Owner-managed website support destination.
---

The website support destination uses the existing published footer Telegram setting. Separate Bot, Mini App, and Channel destinations retain their own configuration.

**Why:** The Owner requested one website support setting, not a global replacement of every Telegram link. Generic Telegram branding alone does not establish that a link is for support.

**How to apply:** Apply the canonical destination to support actions and recognized historical support entries, not arbitrary Telegram social links. Use the existing draft-save and Owner-publish workflow rather than exposing draft changes publicly.

Apply the historical default only to a successfully loaded configuration that confirms an empty value. Unresolved or invalid configuration must not temporarily activate an old support destination.

**Why:** After a support contact changes, linking to the previous username while loading can send customers to a destination the Owner no longer intends.

**How to apply:** Keep icons visible but links non-actionable until resolution succeeds. Draft previews must preserve the distinction between invalid/loading state and deliberately blank state, and all support actions in a preview must share that draft destination.
