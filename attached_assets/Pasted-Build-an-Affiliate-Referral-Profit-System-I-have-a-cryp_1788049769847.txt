Build an Affiliate / Referral Profit System
I have a crypto exchange application similar to Changelly.
My application has two transaction types:
Convert — powered by the Quickex API.
Swap — built and processed internally by my own exchange system.
I want you to build a complete Affiliate / Referral Program for registered users.
1. Affiliate Program Logic
Every registered user should automatically have a unique referral/affiliate code and referral link.
Example:
https://myexchange.com/?ref=USER123
When User A refers User B, User B becomes associated with User A.
The affiliate owner should earn a percentage of the referred user's eligible transaction volume.
The default commission should be configurable from the admin panel.
For example:
0.003 = 0.3%
0.004 = 0.4%
0.005 = 0.5%
IMPORTANT:
Store the commission internally as a decimal/rate and make the admin panel clearly show the percentage.
For example:
0.003 → 0.3%
Do NOT hard-code the commission rate.
2. Commission Configuration
Create an Affiliate Settings section in the Admin Panel.
Admin should be able to configure:
Default affiliate commission rate
Whether the affiliate program is enabled/disabled
Minimum transaction volume required before commission is generated
Minimum payout amount
Affiliate cookie/session duration
Whether commissions apply to Convert transactions
Whether commissions apply to Swap transactions
Maximum commission per transaction, if desired
The commission rate must be editable without changing source code.
Example:
Admin enters:
0.003
The system calculates:
affiliate_commission = eligible_volume × 0.003
If admin changes it to:
0.004
all NEW eligible transactions should use 0.004.
Do not retroactively change commissions that have already been recorded.
3. Referral Tracking
When a visitor opens the website using:
?ref=ABC123
store the referral information.
Use a secure cookie/session mechanism so the referral can survive navigation and registration.
When the visitor registers, permanently associate the new user with the referring affiliate.
Database should contain something similar to:
users.id
users.affiliate_code
users.referred_by_user_id
users.created_at
Prevent obvious self-referrals.
A user must not be able to refer themselves.
Do not allow users to change their referrer after registration.

5. Transaction Commission Calculation
The affiliate system must integrate with BOTH transaction systems.
Convert
When a Convert transaction is completed successfully through the Quickex API:
Identify the user who performed the transaction.
Check whether that user has a referrer.
Determine the eligible transaction volume according to the configured rules.
Calculate the affiliate commission.
Create an immutable affiliate commission record.
Example:
Transaction volume:
$1,000
Affiliate rate:
0.003
Commission:
$3
Only create the commission after the transaction reaches the configured successful/completed status.
Do NOT pay commission for:
failed transactions
cancelled transactions
expired transactions
pending transactions
transactions that are reversed/refunded
Use the actual completed transaction status from the Quickex integration.
Swap
When an internally processed Swap transaction is successfully completed:
Identify the user.
Check whether the user has a referrer.
Calculate the eligible volume.
Calculate the affiliate commission.
Record the commission.
The affiliate system must not depend on Quickex for Swap transactions.
6. VERY IMPORTANT: Define "Volume"
Do not simply assume that any numeric amount in the transaction database is USD volume.
Create a consistent eligible_volume_usd value for each completed transaction.
For example:
If a user swaps:
1 BTC → USDT
and the transaction's USD-equivalent completed volume is:
$60,000
then:
$60,000 × 0.003 = $180
affiliate commission.
Use the existing exchange pricing/conversion data where available.
If the system cannot reliably determine USD-equivalent volume, do NOT silently calculate an incorrect commission. Instead, flag the transaction for admin review or use the configured base-volume calculation.
Document exactly which field is being used as eligible volume.

8. Prevent Duplicate Commissions
This is extremely important.
The same transaction must NEVER generate affiliate commission twice.
Create a unique constraint/index based on the transaction ID and affiliate commission relationship.
For example:
unique(transaction_id, affiliate_user_id)
The commission creation process must be idempotent.
If a webhook from Quickex is received multiple times, it must not create duplicate commissions.
The same applies to internal Swap transactions.
9. Transaction Status Handling
Affiliate commissions should only be created when a transaction is definitively completed.
For example:
pending → completed
should generate the commission.
But:
pending → failed
should generate nothing.
If a completed transaction is later reversed/refunded, create a corresponding reversal ledger entry rather than deleting the original commission.
Never delete financial/affiliate ledger records.
