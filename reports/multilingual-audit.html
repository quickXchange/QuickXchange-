2. Missing translations found and fixed

  • Shared catalog now includes 1,880 customer text entries and 744 authentication/account text entries. These are catalog entries, not a count of distinct English phrases; some compatibility keys intentionally share the same source text.
  • Zero missing customer/authentication entries were found in the final compiled dictionaries for all seven languages.
  • Resolved 48 key-to-key source aliases that exposed raw customer translation identifiers in navigation, and updated their foreign-language values.
  • Corrected 43 outdated authentication interpolation contracts against the current English resource.
  • Registered and translated 360 additional current public-copy, paragraph, category and validation source strings; reviewed 71 unchanged English UI phrases. Legitimate native cognates and canonical acronyms may remain spelled identically.
  • Final targeted fixes cover linked FAQ answers, Track an Order/Contact Us link labels, Support 24/7, Clear order flow, Get started quickly, Market Insights and QuickXchange Updates.
  • Missing known keys resolve through the configured fallback and then the safe English source, never a raw translation key.

3. Hardcoded strings and shared controls

Customer text was migrated into the existing dictionary system and shared display boundaries across Website and Mini App: navigation, widgets, selectors, forms, validation, feedback, loading, tracking, order details, account/dashboard, public information pages and footer. Nested text leaves and module-level navigation metadata were corrected; language-independent metadata identities remain stable.

Both apps use the same translation provider and Admin language settings. Admin → Languages exposes the seven enabled-language controls, an enabled fallback language and searchable translation editing with permission checks, interpolation validation and revision-conflict protection. Locale selection persists in shared browser storage; dictionary changes refresh through events, focus/reconnect and polling. No second translation store was introduced.

Authentication text is assembled from the same shared dictionary and Admin overrides. Add-on presentation uses this same language source; fee calculations were not changed.

4. RTL and layout

RTL was intentionally excluded. All supported languages remain LTR. Ukrainian Mini App entry at 390 × 844 was checked with no horizontal page overflow; public Website locale samples remained readable. Long-text overflow across every protected screen and every locale is not fully verified.

  • 19 automated translation tests passed: all seven dictionaries, current authentication resource and Admin override projection, interpolation fidelity, exact canonical payment values, source lookup, no raw alias values, configured fallback, exact supported-language list and already-localized feedback switching without altering frozen values.
  • Shared-library, Website, Mini App and API TypeScript checks all passed.
  • API language settings were checked as read-only/no-store. Enabling/disabling availability was verified with browser-only fixtures, not real Admin setting mutations.
  • Final fresh screenshots confirmed the Website FAQ renders without a root exception and the Mini App shows its language selector and Telegram connection screen.

These are not presented as passing tests.

6. Remaining content, limits and why

  • Protected Mini App testing was blocked because the preview bridge replaced synthetic Telegram initialization data with an empty value. A second, browser-only auth-module fixture did not render the protected app. Testing stopped after those alternatives; no real Telegram bootstrap, role grant or financial mutation was used to force access.
  • The initial browser report found residual FAQ/footer/home/category copy. Those confirmed issues were repaired afterward; final dictionary/type checks cover the repairs, but there was no third complete browser pass.
  • Published blog article prose has not received a complete per-language editorial review; Blog interface text was the focus. A blanket no-mixed-language claim for article bodies would be inaccurate.
  • New or subsequently edited Admin-authored copy that is not registered in the source catalog may retain its original text. A separate future improvement can register new copy and queue translations for review.
  • Official brands/provider names, asset symbols, network codes, addresses, transaction hashes, order IDs and exact payment values intentionally remain canonical.
  • The literal suffix aaa already present in the published footer title was preserved rather than silently changing existing content.
  • Generated legal/financial prose translations warrant native-language editorial review before publication.

Scope protections

Financial calculation, order lifecycle, Quickex, WhiteBIT, monitoring, deposit and settlement logic was not intentionally changed. Financial API error text is localized at presentation boundaries; canonical codes and values remain intact. Development gained only the language configuration schema and endpoints required for shared controls. Production was not migrated or published.
